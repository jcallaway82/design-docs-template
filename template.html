1. Overview

This page is both a starting skeleton and a live component gallery for the design-document system. Copy this file and the lib/ folder to start a new document suite, then delete the sections you don't need. Every component below renders exactly as it will in your document — open this file directly from disk (file://) to confirm the whole system works offline, including Mermaid diagrams.

Body text is 0.9rem on a 1.7 line height. Use strong for key terms on first introduction, inline code for identifiers, field names, and message names, and links like this cross-reference to connect related documents.

4. Callouts & Feature Boxes

Note: Blue callout for scope statements, "how to read this document" guidance, and neutral supplementary information.
Caution: Amber callout for gotchas, easy-to-miss constraints, and behavior that surprises implementers.
Breaking: Red callout for breaking changes, deprecations with hard deadlines, and unrecoverable failure conditions.
Resolved: Green callout for confirmed decisions and closed questions.
Why this lives here: the cross-note explains a design decision in place — why a field appears at multiple levels, why a component owns a responsibility, why the obvious alternative was rejected. Use it liberally; it's the highest-value writing in the document.

Feature Box — CPNN error-code scheme

Feature boxes hold multi-paragraph spec blocks that deserve visual separation: numbering schemes, implementation guidance, timeout tables. Color the left border by topic — teal for identifier/code schemes, amber for timing and cautionary guidance, blue for general.
