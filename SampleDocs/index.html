CLAWE UI — Design Documentation

Design-doc hub for the CLAWE Interactive Emitters App — a standalone application STS drives over the network to author and run closed-loop adaptive radar waveforms

Version: 1.8 Status: Living index Date: October 2026

1. Overview

CLAWE UI (the "CLAWE Interactive Emitters App") is a standalone C#/WPF/.NET application — its own process, own executable, own SQLite database — that lets a user author closed-loop CLAWE radars (radars that adapt their waveform in response to jamming) and that STS connects to over the network to play those radars inside static scenarios. It is not a PRISM plugin; it is architecturally independent of STS but built to look, feel, and be organized like it.

Runtime shape (per CLAWE UI Requirements.pptx slide 2 and the 2026-09-08 interface meeting): an always-on proxy process listens on the network and launches single-purpose views on request — a singleton Maintenance view (the only writer to CLAWE DB, one instance at a time) for authoring, and 0..n Execution views launched by HOCA to run an assigned radar mode. STS and HOCA connect to the proxy, not to a view directly.

Where the build is: iteration 4 (v0.4.0) is built on feature/interface-b, not yet committed — the proxy plus split maintenance/execution process model, a context-per-operation database layer with a unit-of-work Save, and interface B over RabbitMQ (RequestRadars, LaunchMaintenanceUiCommand, RadarModifiedEvent). Iteration 3 (v0.3.0) is merged to master. The delivery plan (timeline Draft v5) now puts a simulated running radar first: the buyer-demo milestone is iteration 7. See Planning & status below for the delivery plan and the rolling iteration review.
